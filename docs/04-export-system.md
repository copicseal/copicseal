# 04 — 导出系统

## 概述

导出系统是 Template 与 Collage 共用的底层能力，用于将 Workspace 中的真实渲染结果输出为图片文件。

导出系统属于基础设施层，不属于任何单个 feature。渲染结果的编码与保存通过 Platform Contract 完成，以支持 Web 与 Tauri 两种运行环境。

---

## 4.1 设计目标

- 保证预览与导出结果一致
- 支持 Template 与 Collage 两类来源
- 支持单次导出与批量导出
- 支持稳定的进度、取消与错误反馈
- Web 与桌面端均可完成导出；根据平台能力选择目录保存或下载
- 导出尺寸由目标像素决定，不随窗口大小或设备像素比漂移

---

## 4.2 基础链路

```txt
React
↓
DOM
↓
渲染基准解算
↓
snapDOM
↓
Platform Export Service
├── encode PNG / JPG
└── save to directory / download
```

### 说明

- 导出内容必须来自 Workspace 的真实渲染区
- 不允许维护一套与预览分离的隐藏导出模板
- 渲染稳定性由 `core/renderer` 负责
- 导出任务调度由 `core/scheduler` 负责
- 渲染基准的读写由导出服务通过适配器发起，DOM 由 Template 页面持有
- Platform Provider 负责格式编码和宿主相关的保存方式

### 字体内联

快照的实现是「把 DOM 序列化进 SVG 图片再栅格化」，而 SVG 图片文档是独立文档，
拿不到当前文档的 `@font-face`，也未必能取到系统字体表。不处理的话，导出里的文字
会退回到浏览器默认字体（衬线），字宽一变就会出现文案溢出画框、本该一行的内容换行。

因此导出前显式内联字体：

- `embedFonts: true`：把画布内实际用到的 `@font-face`（如应用自带的 Inter）抓成 data URL 内联
- `localFonts`：用户在设置里选的**系统字体**没有 `@font-face`，需要由平台侧
  （`inline_system_font`）按画布上用到的字符**子集化**后返回一条 data URL
- 两条路都拿不到时由字体栈里的通用字体兜底：画布根写的是
  `"<用户选的族名>", sans-serif`，模板自带的字体栈（如等宽栈）本身就完整，原样使用
- 平铺水印的瓦片是内联 `<svg>` + `<pattern>`（不是 data URL 背景图），因此它属于快照 DOM 的
  一部分：字体同样走继承 + 内联，瓦片文字也进 `textContent`，会被一并纳入子集
- 子集化是必须的：中文字体原始文件动辄几十兆（行楷 85 MB、宋体 64 MB），整体内联
  既慢又会被 WebKit 整块丢弃；只保留画布上出现的字形后通常只剩几 KB
  （实测：行楷 85 MB → 7 KB，渲染结果与系统原生渲染逐字一致）
- 集合字体（`.ttc` / `.otc`）的子集化顺带解决了「浏览器只认集合里第一个字型」的问题：
  导出的是我们按族名挑中的那个字型（下标），并优先挑常规字重、与族名语言标记
  （`SC` / `TC` / `HK` / `JP` / `KR`）一致的 face
- macOS **按需下载**的字体（行楷、宋体等）在 CoreText 里是内存字型，没有文件路径，
  平台侧直接从内存字节子集化
- 子集必须带 Unicode `cmap`：浏览器拒绝只有 Mac Roman 码表的字体（子集化库里选
  `CmapTarget::Unicode` 就是为了这个）
- 内联与否会打日志（`[snapshot] 已内联字体 …` / `… 字体无法内联 …`），
  便于在导出异常时确认字体有没有被内联

## 4.3 输出档位

一次导出由一个或多个**输出档位**组成，每个档位独立描述一组尺寸与编码参数。

| 字段 | 说明 |
|------|------|
| `fileName` | 导出文件名，不含扩展名；留空表示自动命名，扩展名始终由 `format` 决定 |
| `format` | `PNG` / `JPG` |
| `width` / `height` | 目标框尺寸（像素），两轴必填 |
| `scale` | 位图倍率 |
| `quality` | 编码质量，仅 JPG 生效 |

约束：

- 档位数量至少为一，支持增删
- 各档位互不影响，独立解算、独立编码
- 目标尺寸缺值或非正数时不允许导出
- 文件名留空即随目标尺寸自动变化，手填后不再被覆盖，清空即恢复自动

### 默认档位

档位属于单张照片，但可以把当前这组档位**存为默认档位**（模板页导出面板里的同名按钮）：

- 默认档位写入设置（见 [05 数据模型](./05-data-models.md) 的 `output.presets`），跨会话保留
- 之后导入的图片自动套用默认档位；已经调过档位的图片不受影响
- 默认档位可以在设置 → 边框水印 → 导出里逐个删除，删空即等同于没存过
- 没有存过默认档位时，新导入的图片从内置的单个 2000×2000 PNG 档位开始
- 档位不齐（目标宽高缺值或非正数）时不能存为默认档位

### 已知限制：暂不支持 WebP

macOS 端渲染在 WKWebView 里，它不支持用 canvas 编码 WebP：请求 `image/webp` 时
`toBlob` 会静默退回 PNG，产出的是一个后缀为 `.webp`、内容却是 PNG 的文件
（体积与 PNG 相同，质量参数完全无效）。Windows 端的 WebView2 支持该编码，但当前
按统一行为处理。

因此在 WebP 编码挪到宿主侧（Rust 侧 `image` crate 已支持有损 WebP）之前，`format`
只开放 PNG 与 JPG。扩展名映射同时做了运行期收敛，避免持久化的历史配置再产出后缀与
内容不符的文件。

## 4.4 渲染基准与尺寸解算

### 渲染基准

模板的几何必须全部表达为渲染基准的倍数。基准以 CSS 变量 `--co-base` 提供，其值即**画布宽度**：

```css
padding: calc(var(--co-base) * 0.05);
font-size: calc(var(--co-base) * 0.022);
```

约束：

- 模板内禁止出现 `px`、`rem`、`vh`、`vw` 等绝对单位与视口单位
- 允许 `em`、`%` 与无单位比值，它们随基准等比变化
- 模板参数的数值字段是无单位比例，不是像素值
- 不得通过 `html { font-size }` 或全局 `rem` 实现缩放

### 尺寸解算

导出时按档位的目标框反解基准，使画布在目标分辨率下**真实重排**，而不是把小尺寸结果放大：

```txt
以探针基准渲染
↓
测量画布布局尺寸
↓
按 contain 反解出命中目标框的基准
↓
应用基准并等待渲染稳定
↓
捕获
```

因为 `--co-base` 就是画布宽度，内容高宽比与基准无关，因此一次测量即可线性反解：

```txt
base = min(目标宽, 目标高 / 内容高宽比)
```

推导结果：主导轴精确命中设定值，另一轴按比例推导，不补边、不变形。测量必须使用布局尺寸（`offsetWidth` / `offsetHeight`），不得使用受变换影响的边界矩形。

### 背景与尺寸

渲染区由**画框**与**画布**两层组成：画框在最外层，承担背景填充与内边距；画布是模板本身，几何全部是 `--co-base` 的倍数。

背景模式直接决定目标框的角色：

| 背景 | 画框 | 画布 | 1280×720 + 方形画布的结果 |
|------|------|------|----------------------|
| 无背景 | 贴合画布 | 按 contain 命中目标框 | **720×720**（宽度按内容比例重算） |
| 纯色 / 照片模糊 | **精确等于目标框** | 在扣除内边距后的内容盒内 contain | **1280×720**（模板内嵌，其余由背景填充） |

约束：

- 内边距与模糊半径都写成画框宽度 `--co-frame` 的比例，不出现绝对单位
- 竖直内边距同样以画框宽度为基准，因此不依赖画框高度
- 模糊背景的外扩量取模糊半径的两倍，避免模糊之后画框边缘透出
- 画框属于框架层，其像素尺寸由解算逻辑直接设置，不受"模板内禁止绝对单位"的约束
- 导出前必须挂起预览自适应，避免其覆盖解算结果

#### 预览与导出的目标框

解算规则只有一套，预览与导出的区别只在于**目标框是谁**：

| 场景 | 目标框 |
|------|--------|
| 导出 | 档位宽高，逐档独立解算 |
| 预览 · 适应 | 预览区可用区（视口扣掉留白） |
| 预览 · 缩放档位 | 让照片宽度命中「原始像素宽度 × 百分比」所需的目标框（`100%` 即 1:1） |

由此产生两条需要明确的结论：

- 无背景时导出尺寸由画布比例决定（画布在档位框内 contain），有背景时精确等于档位尺寸
- 预览与导出的目标框比例可以不同：画框与画布的相对关系（内边距、contain）两边一致，但背景留白的绝对比例随目标框比例变化。预览用于判断构图，最终留白以档位尺寸为准

### 倍率与像素比

- 输出倍率**只**来自档位的 `scale`，在解算尺寸之上做位图超采样
- 光栅化像素比固定为 `1`，避免设备像素比隐式放大结果
- 导出分辨率元数据（`dpi`）只写入 EXIF，不参与尺寸计算

## 4.5 Template 导出

Template 导出支持：

- 导出当前图片
- 批量导出当前资产列表
- 批量导出时，每张图片按各自的模板、参数、背景与导出档位输出
- 每个档位独立解算基准并输出
- 背景随该图片自己的模板与用户调整一同生效

模板配置属于图片本身，因此批量导出不是把一套样式复制多份，而是逐张按自身配置渲染。

档位不完整（目标宽高缺失或非正数）的图片会被跳过，导出结束后提示跳过数量。

导出前必须确保画布内的图片已加载完成、EXIF 已就绪，否则会按占位比例或空元数据渲染，导致尺寸偏差或水印缺项。

导出期间预览自适应必须挂起，避免其改写解算出的基准。

---

## 4.6 Collage 导出

Collage 导出支持：

- 导出当前拼图结果
- 保持与当前画布布局一致
- 复用统一输出档位结构，以单档形式提交

Collage 不参与模板的基准解算，其输出尺寸由画布自身的渲染尺寸与档位倍率决定。

---

## 4.7 批量导出状态

导出状态至少包括：

- 当前任务来源（Template / Collage）
- 当前文件名
- 已完成数量 / 总数量
- 当前档位
- 取消状态
- 错误信息

---

## 4.8 命名与目录

系统支持：

- 默认导出目录
- 用户选择导出目录
- 按来源与档位生成默认文件名

浏览器不支持目录选择或直接写入时，系统应以下载方式导出，并保留建议的文件名；不得将桌面目录选择器作为 Web 的前置条件。

导出统一写入设置 → 导出里的「文件导出目录」（`output.default_path`），过程不再弹任何保存对话框；读不到配置时退回逐次保存对话框作为兜底，浏览器环境仍以下载方式导出。

Template 命名：

```txt
{原始文件名}@{宽}x{高}.{格式}
```

这是档位文件名留空时的自动命名，会随目标尺寸一起变；文件名也可以手填，填过之后
不再被自动覆盖，扩展名始终跟随 `format`。非法字符会被替换，同批次内重名时追加序号。

Collage 命名：

```txt
拼图@{宽}x{高}.{格式}
```
