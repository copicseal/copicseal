# 09 — 拼图系统

## 概述

Collage 页面负责多图拼接与导出，是与 Template 平行的独立功能域。

路径：

```txt
/collage
```

核心原则：

```txt
Collage 与 Template 完全独立
```

禁止：

- 共享编辑器
- 共享布局逻辑
- 共享状态

仅共享：

- Export Pipeline
- Asset Infrastructure

## 9.1 页面结构

```txt
┌──────────────────────────────────────────────────────────────┐
│ Header（窗口标题）                                            │
├──────────────────────────────────────────────────────────────┤
│ Toolbar：撤销 / 重做 · 选择·平移 · 自动填充 · 复位 · 导出        │
├──────────┬────────────────────────────────────┬──────────────┤
│ 布局库    │ Collage Preview                    │ Properties   │
│ 网格/长图/│                                    │ 编辑对象      │
│ 自由      ├────────────────────────────────────┤ 单格 / 画布   │
│          │ Collage Assets                     │              │
└──────────┴────────────────────────────────────┴──────────────┘
```

- 三栏由 `shared/layouts/business-workbench.tsx` 的 `library` 槽位提供；中栏内部再纵向拆「预览 / 素材」
- 素材区与「边框水印」模块同款外壳：固定高度、不可拖拽分隔（`assetsResizable={false}`）、顶部边框上挂一个
  「收起 / 展开」按钮（悬浮提示 + `aria-expanded`），收起后只留一行「素材 N 张 · 已放入 M 格」
- 拼图里**没有原生滚动条**：画布视口与素材条都用共享的 `ScrollArea`
  - 画布视口：`scrollbarOrientation={exporting ? 'none' : 'both'}`（导出时会临时放大画布，这时不显示滚动条免得预览抖动），
    `viewportRef` 交给画布测量可用区（视口尺寸只由容器决定，不会和内容测量形成回环），内层再放一个
    「最小尺寸 = 视口」的居中容器：装得下时居中、装不下时随内容增长（照模板预览的写法）
  - 素材条：`scrollbarOrientation="horizontal"` + `horizontalWheelScroll`（滚轮直接横滚），
    `viewportClassName="[&>div]:!block [&>div]:h-full"`：
    Radix 套的那层是 `display: table`，而**表格的 `height` 只当最小高度**，`ul` 的 `h-full` 会解析成内容高度
    （被图片原始比例撑高），卡片就会溢出到视口外、底部被裁掉（表现为「上边距很大、没有下边距」）。
    先把那层改成 `block`，它的 `height:100%` 才有效，卡片高度才等于素材区高度（实测卡片 = 视口高 − 上下各 12px，纵向溢出 0）
  - 滚动条本身用 Radix 的默认 `type="hover"`：**悬停时才出现**（与「边框水印」面板一致）。想让它常驻可以给这两个 `ScrollArea` 传 `type="always"`
- 属性面板最小宽度 260（里面有宽高输入与档位按钮，再窄会被挤到换行），与模板页取值一致
- 视觉与交互沿用「边框水印」模块的既有习惯：`CoPanelSection` 分区、`Button` 档位、`border-primary bg-primary/5` 选中态、预览底部的档位按钮条，以及同一份「常用尺寸」配置
- 组件位于 `features/collage`，各自单一职责：
  - `collage-layout-library.tsx` 左侧布局库与模式面板
  - `collage-canvas.tsx` 画布渲染与全部画布手势
  - `collage-toolbar.tsx` 顶部工具条
  - `collage-assets-panel.tsx` 素材区
  - `collage-properties-panel.tsx` 右侧属性面板
  - `collage-page.tsx` 组装、导出编排与素材同步

## 9.2 三种布局模式

| 模式 | 说明 | 槽位来源 |
|------|------|----------|
| 网格 `grid` | 从布局库选模板，槽位坐标落在 12×12 单位网格上 | 布局的 `slots` |
| 长图 `long` | 按素材顺序首尾相接，支持竖向 / 横向与对齐方式 | 素材数量（每张一行/一列） |
| 自由 `free` | 每张独立摆放，位置与大小是画布百分比 | 素材数量 |

- 网格模式下槽位数量严格等于布局的格子数；长图 / 自由模式跟随素材数量（导入会长出来，删除素材会收回去），
  按「不同素材数」而不是「已填格数」兜底，同一张图被引用两次不会多顶出一行空白
- 切换布局时会把还没放进去的素材按顺序补进空位（工具条的「补齐空位」是同一套逻辑），
  不会出现「换个布局图就少了」
- 长图横轴尺寸（`canvas.longSize`）与对齐（`longAlign`）在左侧「长图」面板里设置
- 长图的**横轴**是固定那一侧：竖向导是宽、横向导是高；主轴（竖向的高 / 横向的宽）一律由内容撑开。
  把主轴写死会把后面的行/列裁掉——横向长图曾经就是这样（画布 445×445，三列排到 1359px 只看得见第一列）
- 自由模式的默认位置按三列铺开，双击复位单张、面板里可整批复位
- 自由模式允许图片互相压住（自由摆放本来就会重叠），层级就是槽位顺序；「单格」面板里的
  「上移一层 / 下移一层」用来调谁在上面，移动后选中项会跟着走

## 9.3 布局库

- 覆盖 1–20 张：1–6 / 9 / 12 / 16 张是手工挑选的常用构图，7、8、10、11、13–15、17–20 张按张数生成「均分」与「主图 + 副图」两种
- 生成规则：每行 2/3/4/6 张（都能整除 12，槽位坐标才是整数），并按「格子宽高比最接近 1」挑选分行方案
- 按「N 张图」分组展示线框缩略图，顶部下拉可跳转到指定张数
- 数据校验（脚本一次性核对）：81 个布局、无一重复 id、无空洞（槽位面积合计 144）、无重叠

## 9.4 单格编辑

工具栏的「选择 / 平移」决定画布上拖拽的含义：

| 工具 | 拖拽 | 滚轮 | 双击 |
|------|------|------|------|
| 选择 | 拖动画面换位（移动插入，可跨格重排） | — | 复位该格 |
| 平移 | 移动该格图片（1:1 跟手，见下） | 缩放该格 | 复位该格 |

长图模式里每行都是等比缩放的整张图，没有「取景」可调，因此拖动一律按换位处理，与当前工具无关。

- 图片位置用百分比偏移（-50 ~ 50）映射到 `object-position`，因此不会拖出空白
- **方向与幅度**：`object-position` 的百分比是「图片相对框的锚点」，增大它会把图片往左上推，所以写入时要**取反**
  （`50 - offset`），让「偏移量为正 = 图片向右/下滑」，也就是拖动时图片跟着指针走；
  幅度必须按「图片按 cover 溢出格子的像素量 × 缩放」换算（1% 对应的是溢出量而不是格子宽度），
  否则图片只会走指针的一半。某轴本来就没有溢出（cover 已贴边）时不动该轴，避免存下无意义的值
- 缩放、旋转、水平/垂直翻转、单格圆角都在右侧「单格」面板里，另外提供「替换 / 清空」
- 网格模式每格还能选填充方式：**裁切填满**（`object-cover`：按格子比例放大图片、裁掉超出部分，
  照片比例与格子不一致时**看不到全图**）或**完整显示**（`object-contain`：整张图缩进格子，比例不一致时留出画布背景）。
  面板里对当前选中项有一句说明，避免「填满」被理解成「把整张图缩进格子」
- 快捷键：`⌘/Ctrl + Z` 撤销、`⌘/Ctrl + Shift + Z`（或 `Ctrl + Y`）重做、`Delete` / `Backspace` 清空选中格、`Esc` 取消选中；
  在输入框里打字时这些键不抢（属性面板里几乎全是输入框），页面不可见时也不挂监听
- 画布缩放手势期间只改 `present`，松手时回到手势起点再提交一次，撤销栈里只留一条记录
- 画布上的拖拽与素材区拖拽一样把指针事件挂在 `window` 上，不依赖 `setPointerCapture` 的重定向：
  光标移出这一格（甚至移出画布）时拖动不会断；空槽位也会等 `pointerup` 来判定「点击填充」
- 撤销 / 重做各 60 步，覆盖布局、画布参数、单格调整与素材同步以外的全部用户操作
- 工具栏「补齐空位」只往空槽里补素材，已有格子的取景与缩放原样保留；整块重排（会重置取景）只放在
  自由布局面板的「按素材顺序铺开」里

## 9.5 素材区

- 导入：按钮选图、把系统文件拖进素材区、`Ctrl/Cmd + V` 粘贴剪贴板里的图片（页面不可见时不响应）
- 放入：按住素材卡拖到画布任意一格；双击素材卡放进第一个空格子；单击画布里的空格子会填入当前素材
- 拖动用**指针事件自绘**，不用 HTML5 拖放：桌面端为了接收系统文件拖入，开启了 Tauri 的原生拖放
  （`onDragDropEvent`），它会截走 webview 内的 `dragstart` / `drop`，导致「素材拖不进画布」。
  自绘拖拽的指针事件挂在 `window` 上（不依赖 `setPointerCapture`），光标离开素材卡、跨到画布上都不会断；
  拖到窗口外松手或失焦时只收尾、不落图
- 拖动过程中跟随光标显示素材缩略图浮层，悬停的格子高亮；拖拽结束后的 click 不再当作「选中素材」
- 替换：素材卡上的替换按钮（保留槽位引用，换的只是图片内容）
- 删除：素材卡上的删除按钮，同时清掉画布里的引用并把后续图片前移补洞
- 素材与槽位的对齐只在「素材列表变化 / 切换模式」时发生，手动清空的格子不会被填回去

## 9.55 设置里的默认值

设置 → 拼图分两页，写进配置的 `collage` 段（见 `docs/05`）：

- **默认项**：布局模式、默认网格布局、画布比例（含自定义）、间距 / 边距 / 圆角 / 阴影、背景色、长图方向 / 对齐 / 横轴尺寸
- **导出**：格式、质量、倍率、目标尺寸、锁定比例

语义（面板里也写了）：

- 只在**新建拼图**（本地还没有拼图状态）与拼图页的**「恢复默认」**时被读
- 已摆好的拼图不会被改；判定是**逐块**的——画布、导出、布局各自看是否仍是出厂默认，
  用户调过的部分保持原样（读配置是异步的，只按「整体是否等于默认」判断会因为在读盘期间导入一张素材而失效）
- 拼图页「画布」与「导出」两个分区各有一个**恢复默认**，恢复的是**设置里**的值而不是出厂值；
  参数已经等于该默认值时按钮置灰，恢复只占一条历史（可 `⌘Z`）

设置侧顺带修了一个老问题：连续点档位/拖滑杆时，回调闭包里的 `config` 还是旧值，
逐次保存会互相覆盖（后一次把前一次写回旧值）。现在所有「改一块」的操作都以 `configRef`
里的最新值为基准（`patchConfig`）。

## 9.6 画布与导出

- 画布按设计基准渲染：网格 / 自由模式基准宽度 1000，长图基准（横轴）是 `canvas.longSize + 2 × padding`
- 「画布」分区头部有**恢复默认**：一次把比例、间距、边距、圆角、阴影、背景色与长图参数还原成默认值
  （`resetCanvas`，只落一条历史、可撤销；锁着导出比例时会顺手把导出高度按默认比例重算），
  参数已经全是默认值时按钮不可点（`isDefaultCanvasState`）
- 网格 / 自由的画布**宽高都写成显式像素**（`appliedWidth × appliedHeight`），**不要只靠 `aspect-ratio`**：
  WebKit 不把 `aspect-ratio` 派生出来的高度当作「确定高度」，格子里 `img` 的 `height:100%` 于是失效、
  图片按原始尺寸渲染——预览里每格只露出图片中间一小条，而**导出正常**（导出适配器本来就会把画布宽高写成显式像素，
  百分比链自然成立）。这个差异只在 WKWebView 里出现，Chromium 下 `aspect-ratio` 的链是通的，所以浏览器端测不出来
- 设计尺寸解算：网格 / 自由两轴都由比例决定；长图只有横轴已知，主轴那一侧从**实测宽高比**反推
  （横向与竖向各反推一侧），再拿两轴算 fit
- 「适应」算的是**实测宽高比**（`实测高 × 设计宽 ÷ 实测宽`），不能拿假定倍率去反推高度：
  长图高度由内容决定，用错倍率会让 fit 在「撑满宽」与「撑满高」之间来回跳，长图永远塞不进视口
- 预览缩放（适应 / 50% / 100% / 200%）**不持久化**：它是「看」的状态，重启后一律回到「适应」；
  否则上次停在 200% 时重开看到的只是被放大的片段，很容易误判成「图片没缩放进格子」
- 单格缩放的滚轮监听挂在 `window` 上（处理时判断事件是否落在画布内）：没有素材时画布走空状态分支、
  视口元素不存在，effect 里取 ref 会是 null 且不会再重跑，挂视口元素等于监听永远绑不上
- 间距、边距、圆角、阴影都用 `calc(设计值 * var(--co-collage-scale))`，`--co-collage-scale` 等于「当前渲染宽度 / 基准宽度」

间距与边距在各模式下的落点（这几条曾经是错的，改的时候别再想当然）：

| 模式 | 间距 | 边距 |
|------|------|------|
| 网格 | 每格自身内缩 `gap / 2`，格与格之间合起来是 `gap` | 参与坐标换算：可用区先扣掉 `padding - gap / 2`，最外圈留白正好等于 `padding` |
| 长图 | flex 容器的 `gap` | flex 容器的 `padding` |
| 自由 | 无（自由摆放没有格与格的概念，面板里不显示） | 作为一圈安全边：位置与大小按「画布扣掉边距」的可用区换算 |

网格与自由模式的槽位是绝对定位，**绝对定位的包含块是祖先的内边距盒**——父容器写 `padding` 对它们没有任何作用，所以边距必须显式进入坐标换算（`getPaddedSlotRect` / `getFreeSlotRect`）。
- 导出时 `sizeAdapter` 把画布直接切到目标像素（宽度 = 目标宽，`--co-collage-scale` 等比放大），于是「预览所见」就是「导出所得」，长图高度由内容决定
- **导出期间必须冻结预览尺寸**：画布被改大后 `useElementSize` 会重新测量 → `fitScale` 重算（长图模式的 fit 依赖实测宽高比）
  → React 把宽度写回预览值，导出的那一帧就白改了（实测表现为长图导出落盘成 139×428 的预览图）。
  做法与模板预览的 `suspendAutoFit` 同理：导出中沿用「开始导出前」的倍率与宽度，React 的 style diff 就不会去覆写适配器写进去的尺寸
- 导出参数：PNG / JPG、JPG 质量三档、倍率 1x/2x/3x、目标宽高、锁定画布比例（按画布比例联动高度）
- 常用尺寸与「边框水印」共用同一来源（设置 → 导出 → 常用尺寸），面板里的下拉直接取这份清单；清单为空时只给一行「可在设置里添加」的提示
- 导出过程在画布上盖一层遮罩（`正在导出…`），挡住导出解算造成的尺寸跳变，与模板预览的处理一致
- 拼图是整块画布，因此只有「导出」一个动作，没有模板页那种「批量导出」（那会导出同一张画布的 N 份副本）
- 画布上一张图都没有时，工具条与属性面板的导出按钮都不可点（否则只会导出一张空白图）
- 导出直接落盘到配置里的保存目录，不弹保存对话框
- 文件名按**最终像素**给（`拼图@4096x4096.png`、长图 `拼图@2048x6317.png`）：尺寸适配完成后（截图前）用真实元素尺寸
  × 倍率回写 preset 的宽高，导出流程本来就是「先截图、后命名」，所以名字与落盘内容永远一致
- 空格子只是编辑期的提示：导出时该格只留背景，`+` 与「第 N 格」不会印进图里

交互与导出的端到端校验（真实 Chrome + CDP 驱动，脚本在 `/tmp/collage-e2e/`：`run.mjs` 管导出、`interact.mjs` 管交互）：导入三张真图 → 选 2×2 布局 →
逐格点入 → 分别以 1x / 2x / 切 4:3 后 1x 导出，再用 Pillow 量落盘文件。实测：2048×2048、4096×4096、2048×1536，
且留白与间距正好等于设计值 × 倍率（20px 边距 → 41px、12px 间距 → 24~25px，2x 时翻倍）。

真实输入校验（`/tmp/collage-e2e/`，均为 CDP 驱动真实 Chrome，合成事件测不出「挂载时序」这类问题）：

| 脚本 | 覆盖 |
|------|------|
| `run.mjs` | 导入真图 → 排版 → 1x / 2x / 4:3 三档导出 → 用 Pillow 量像素、留白与间距 |
| 长图导出（竖向 / 横向） | 竖向 `2048×6317`、横向 `6316×2048`；行/列宽高、边距与间距都与设计值一致 |
| JPG 导出 | 选 JPG 后质量档位才出现；落盘是真正的 JPEG（`2048×2048`、RGB），不是改后缀的 PNG |
| 自由模式导出 | 按颜色定位各格在成品图里的包围盒，与预览的相对位置/尺寸偏差 ≤3px（2048 宽），层级关系一致 |
| 粘贴导入 | 页面内造一张图塞进剪贴板事件，素材数 3 → 4 |
| 3x 倍率 | `拼图@6144x6144.png`（2048 × 3），名字与像素一致 |

## 9.7 数据模型

`CollagePresentState`：

```ts
{
  layoutId: string;
  canvas: CollageCanvasState;         // 模式、比例、间距、边距、圆角、阴影、背景、长图参数
  exportSettings: CollageExportState; // 格式、质量、倍率、宽高、锁定比例
  slotItems: CollageSlotState[];      // 每格：图片、取景、缩放、旋转、翻转、圆角、自由位置
  annotations: CollageAnnotation[];   // 预留：文字 / 箭头 / 矩形 / 椭圆
}
```

- 持久化在 `localStorage['copicseal-collage-state']`，`version: 2`；旧档（像素偏移）在 `merge` 时收敛到百分比区间
- 槽位带稳定 `id`，只用于 React 复用 DOM，不参与导出
